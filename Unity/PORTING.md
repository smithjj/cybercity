## Conventions

- **Coordinates.** Sim (JS) `(x,y,z)` == Unity `(x,y,-z)`. All world data generated in C# is stored in
  Unity space; oracle dumps compare in sim space. `GameDebug.ToU(x,y,z)` is the only conversion.
  Yaw: JS forward `(-sin yaw, -cos yaw)` in (x,z); yaw 0 = north = sim -Z = Unity +Z.
  Unity camera yaw = `180 - simYaw`; Euler x>0 looks down.
- **Editor discipline** (see EDITOR-CLI.md): `ev.sh` for eval (~5 s budget → `delayCall` for more);
  `recompile --focus` then wait ~15 s before Play; `editor_stop` before editing scripts;
  Play needs `runInBackground=true` + `QueuePlayerLoopUpdate()`; capture `--save_path` must be a
  Windows path; shader errors → `ShaderUtil.GetShaderMessages`, not the console.
- **Determinism.** All generators use the ported `mulberry32` (first oracle) with the JS seeds.
- **Eval snippet quoting:** single-quoted shell strings; anything with quotes → file + `"$(cat f.cs)"`.
- **6000.6.3f1 API deltas (verified by reflection):** `GraphicsDeviceType` is in namespace
  `UnityEngine.Rendering`, member `Direct3D12` (no D3D12). `EditorBuildSettings.scenes` element type is
  `EditorBuildSettingsScene(path, isActive)` (no SceneReference). `ScreenCapture.CaptureScreenshot(string)`
  only (no 3-arg overload). Hand-rolled `TimeManager.asset` must use class id `!u!5` + `Fixed Timestep:
  m_Count/m_Rate` rational (old `!u!29` id is now OcclusionCullingSettings). `GraphicsSettings.defaultRenderPipeline`
  (currentRenderPipeline is get-only).
- **Editor lifecycle:** never `taskkill` the editor (triggers safe mode next launch — subset of assemblies,
  pipeline server half-broken). Clean quit: `unity command menu "File/Exit"` (returns "Invalid response
  format" — that's the server dying mid-response; the exit is clean). Pipeline server only starts if the
  pipeline package is present at first domain load — after `pipeline install`, restart the editor.
  Console `error` entries with `seeded:true` are stale; trust `groundTruth.compilationFailed`.
- **Stale domain hazard — RESOLVED:** `AssetDatabase.Refresh(ImportAssetOptions.ForceUpdate)` via ev
  picks up script AND shader edits reliably (the earlier "edits ignored" episodes were actually broken
  shader-include chains + cached variants, not file-watching). Restart the editor only for package/
  manifest changes. `Temp/` (incl. oracle dumps) is wiped by a restart — regenerate `dump-*.mjs` outputs
  after any restart.
- **Raw SRP shader boilerplate:** `Common.hlsl` alone lacks SpaceTransforms AND `_WorldSpaceCameraPos`
  AND `UNITY_MATRIX_M`; `SpaceTransforms.hlsl` needs the instancing machinery. Use
  `Assets/Shaders/NkCommon.hlsl` (declares UnityPerDraw cbuffer with unity_ObjectToWorld, unity_MatrixVP,
  _WorldSpaceCameraPos + NkWorld/NkClip manual transforms — Unity's custom-pipeline pattern). HLSL notes:
  no implicit vec2→vec3 promotion (add overloads, declared AFTER the float3 version — earlier declaration
  makes the call resolve to itself with truncation → "recursive functions not allowed"); no scalar-splat
  `float3(x)` constructors (DXC rejects); `ShaderUtil` messages can flag unused variants — trust Peek(render).
- **HDRP exposure sign:** fixedExposure is subtractive — EV=-5 brightens 32×, EV=+5 darkens. Review
  shots currently run at EV=-5; parity exposure for phase 2+ comparison is EV=0 (restore before tuning).
- **Numeric fidelity rules (learned via ground oracle):** (1) all JS-derived constants are C# `double`
  (a `float` const like 0.15f poisons downstream double math by ~6e-9); (2) JS `Math.hypot` == fdlibm
  (`a*sqrt(1+(b/a)²)`) — .NET `Math.Hypot` differs by 1 ulp; use `GroundGeo.Hypot2`; (3) THREE.ShapeGeometry
  = mapbox earcut v3.0.2 (ported: `Core/Earcut.cs`) which FILTERS collinear/duplicate points (66 vs 208
  tris); (4) three's `.rotateX(-PI/2)` leaves float32 artifacts `cos(-PI/2)·y` in positions and `cos(-PI/2)`
  in normal z (survive wherever translate doesn't absorb them) — replicated in the oracle; (5) eval snippets:
  no JsonElement indexer — use `EnumerateArray()` + `GetString()`.
- **5 s eval budget:** heavy calls (pipeline assignment, scene save, color-space switch) time out but keep
  running on the main thread — re-invoke idempotently until done.

## Phase 2 — props stage VERIFIED (oracle PASS: 2049 lots, 152 buckets identical)
- **Ported**: `Assets/Game/Buildings/Props.cs` (buildProps: balconies+clutter, hung AC units + instanced matrices, party-wall stacks, drainpipes, ground-floor shutters/doors/posters, roof AC/tanks/stair houses/antennas/dishes/fences/billboards, vending machines, sidewalk clutter; instanced matrices in `BOut.AcM/TankM/PtankM`; 2505 colliders, 92/217 lights).

- **BUG FOUND (critical, affects ALL rotated-geometry normals)**: `BGeom.Matrix3Invert` used the standard ROW-major cofactor formula, but three.js matrices are COLUMN-major — result was `(Mᵀ)⁻¹` instead of `M⁻¹`, i.e. **the normal matrix was the inverse rotation** (normals mirrored across the beam axis). Also the det formula differed (`n11*t11 + n12*t12 + n13*t13` vs three's `n11*t11 + n21*t12 + n31*t13` — different rounding). Fixed by porting three's `Matrix3.invert` element-for-element (n11..n33 naming, t11/t12/t13, exact te placement). Diagnostics that pointed here: JS-only normal multiset had `(0, ±1, ±2.22e-16)` (three's compose double-formula fingerprint) where C# had exact `(0, ±1, 0)`; tilted beam normals appeared sign-flipped between sides. A single-leg hex probe (JS vs C#: q, nm, transformed normals) made it decisive.
- **LESSON — three.js `normalize()` is multiply-by-reciprocal**: `Vector3.normalize`/`Quaternion.normalize` = `divideScalar(l||1)` → `multiplyScalar(1/l)` — `x*(1/l)` ≠ `x/l` (double rounding, 1-ulp diffs). Fixed `SetFromUnitVectors` + `Geom` normal path to `inv = 1/l; v *= inv`. (JS's standalone `norm()` helper in geom.js DOES divide by hypot — mirror per-callsite, not globally.)
- **Probes convention that worked**: JS single-primitive hex probe via node + THREE import; C# via `ev.sh` with `BitConverter.DoubleToInt64Bits(...).ToString("x16")`. Compare q, nm, and one transformed normal — pinpoints which stage diverges.
- All RNG instrumentation removed (C# DrawLog/CylLog/BillboardLog statics, JS __RNGDRAW hook + SEC markers); oracle re-run PASS on cleaned code.
- Next: Alley (`alley.js`, rng 0xA11E), Overlook (`overlook.js`), Cables (`cables.js`, rng 0xCAB1E) → full-buildings oracle; then shaders/atlas/GLBs, `D.BuildBuildings()`, lights.

## Blinding white sky + dead R rain toggle — FIXED (Oct 17)
- **White sky — three stacked causes:**
  1. `AtmoVolume` is saved INACTIVE in Main.unity and nothing re-enabled it. With no scene volume the camera used HDRP's default volume profile: `DefaultHDRISky` + Exposure `Automatic` -> sky pixels clipped to white. `Atmo.EnsureHdrpSkyOff()` (called from BuildSkyDome + `[RuntimeInitializeOnLoadMethod(AfterSceneLoad)]`, so it also covers a standalone player) re-activates the scene volume before the first frame; fallback is a runtime volume with `VisualEnvironment.skyType=None` and `Exposure` Fixed 0 EV.

  3. `Sky.shader` vertex did `NkClip(IN.pos.xyz)` (OBJECT space) on the 1800x camera-following sphere -> the whole dome collapsed to a 0.5 m ball at the origin. Fixed to `NkClip(o.worldPos)`.

A ZWrite-Off dome can never cover it; ZWrite ON would occlude everything beyond the 900 m dome (skyline reaches ~2.4 km). Correct setup = sky type None + color-only dome.
- **Duplicate dome:** BuildSkyDome removed only "skydome" while the editor builder makes "Skydome" (`GameObject.Find` also misses inactive) -> two domes. Now removes case-insensitively and builds one "Skydome".
- **Dead R rain toggle:** the scene has NO GameContext object and PlayMode never called `D.Ensure()`, so `GameContext.I` was null in Play. ## "Fabulously bright pink cars" — hero palette sRGB bug (Oct 17)
- **Symptom:** several cars render as a flat, unlit-looking hot pink (view in `pinktexture-cars.png`) — reads exactly like a missing/broken texture, but vehicles are textureless vertex-tag shaders, and the glass stayed correctly black. 31 of the 384 cars were affected.
- **Cause:** `VehicleTraffic.Palette["hero"]` was the one entry not built with the `C(hex)` helper: `new[] { new Color(0x0a, 0x0a, 0x0c) }`. `Color(int,int,int)` resolves to the FLOAT ctor, so the paint was RGB **(10, 10, 12)** — not 10/255. `MaterialPropertyBlock.SetColor` then applies `GammaToLinearSpace` on upload: 10 -> **158.489**, 12 -> **236.700**. That is an HDR-white albedo ~255x too bright. AgX's highlight rolloff then flattens the over-range body and skews it toward the nearest of the "notorious six" — a slightly blue-biased white lands on magenta, and the grade/saturation makes it pastel pink. The paint-tag geometry still shades, so it reads as a uniform pink *material*, not a lighting bug; the black glass is tag 1 and never sees `_PaintColor`. Same class of error as writing 0..255 shades into any `Color(float,...)`.
- **Fix:** `["hero"] = new[] { C(0x0a0a0c) }` (the KUROGANE is meant to be near-black, matching `three.Color(0x0a0a0c)` in the browser). The 0x07/0x07/0x0a overrides at `HealParkedPaint` and the spawn-kerb hero were already /255 and stay as-is.
- **Detection (reusable):** dump `_PaintColor` from every vehicle `MaterialPropertyBlock` — a legal 0..1 palette value has all components <= 1; any component > 1 means a 0..255 literal got passed through `SetColor` and gamma-expanded. After the fix: `hdrPaint=0/384`; hero cars store linear (0.0030, 0.0030, 0.0037).
- **Verified:** body pixel went from (210,146,207) to (0,9,22); `Temp/shots/hero-fixed.png`, `hero-fixed-rear.png` (rear view of `parked_hero`), `spawn-fixed.png`. Hero cars still show their trim/glass tags and wet reflections.
- Note: `HealParkedPaint`'s `magnitude > 0.01` "already painted" guard is in LINEAR space, so near-black palette colors (hero/kei-black/av) fall below it and get re-rolled every play — harmless (browser re-rolls paints per page load too), but don't read that threshold as sRGB.

## Headlights / taillights — dead tag gates + transposed AgX (Oct 17)
- **Symptom:** no car ever showed a working headlight or taillight (the KUROGANE's signature red tail bar, traffic brake lights, parked hero's headlamps all dark). Once the gates were fixed they lit up **pink**, not white/red.
- **Cause 1 — dead lamp gates:** `VehicleCar.shader` tested `float head = step(3.5,tag)*step(tag,3.5)` (true only at exactly 3.5) and `float tail = step(4.5,tag)` (never). The baked tags are the INTEGERS 3=head, 4=tail (`uv1.x`), so both branches were unreachable; `_LightLv.y` (tail/position on) was ignored and a hardcoded `0.35 +` kept every parked car's tail faintly glowing while its lights were "off". Fix in `VehicleCar.shader`: `isHead = step(2.5,tag)*(1-step(3.5,tag))`, `isTail = step(3.5,tag)`, `tailLvl = isTail*(_LightLv.y*3.2 + _LightLv.z*11)`, plus the JS LED segment pattern along car-local X (new `localPos` varying), head `(0.86,0.93,1.0)*38`, tail `(1.0,0.035,0.02)` — all values from `materials.js makeHeadLight/makeTailLight`.
- **Cause 2 — spawn-kerb hero switched off every play:** `HealParkedPaint` re-applies parked MPBs (they don't survive scene saves) and unconditionally did `_LightLv = 0`. The spawn hero's near-black paint is below the heal threshold, so it was always "healed" and its head+tail lamps were zeroed. Now the heal sets `(1,1,0)` for `parked_hero` (JS index.js sets it explicitly) and zero for every other parked car.
- **Cause 3 — lamps rendered pink:** `AgX.hlsl` copied the standard AgX / three.js `mat3` literals straight into HLSL `float3x3`. GLSL literals fill COLUMNS, HLSL literals fill ROWS, so `mul(M,c)` applied **M^T**. Proof: the intended matrices have row sums of exactly 1.0 (neutral-preserving); the transposed ones sum to 1.106/0.933/0.961, so a neutral white came out `(188,147,241)` violet and a red lamp `(205,85,165)` pink. Fixed by writing the transposed (correct) matrices. Also added the source chain's partial hue preservation (`PostFX.js hueKeep 0.45`): `lerp(AgX(c), c/max(c)*AgX(max(c)).g, 0.45)`. With both, the hero's white DRL reads `(198,194,195)` and the tail bar `(200,86,65)`.
- **Global consequence:** this is a display-transform fix in `AgX.hlsl`, included by every shader — the whole scene loses its old violet wash and gains neutral whites/distinct neon hues (`Temp/shots/agx-spawn-before-after.png`). It is one file; revert that file alone to restore the old grade.
- **Lights.js follow-up:** headlight beams, ground pools, tail/head point lights and AV nav lights are ported in the next section. Only the hero/driven spotlights remain unported (there is no driven car in play mode, so index.js never selects a spotlight car).
- **Van/kei/taxi headlamps — see next section.**
- **Also still different from PostFX.js:** the grade constants are applied to linear values, while the browser applies them to the sRGB-encoded image. A display-space variant was tried and reverted (warm/flatter, no better lamp colours); leave it for a dedicated color pass. `_AgxExposure` is 0.82, set in `BuildingsRuntime`.
- **Verified:** `parked_hero` auto `_LightLv=(1,1,0)` after heal, ordinary parked cars `(0,0,0)`, traffic `(1,1,brake)`; head pixel `(198,196,198)` white, tail `(200,86,65)` red; shader messages 0; shots `Temp/shots/lamp-hero-head.png`, `lamp-hero-tail.png`, `lamp-tail-before-after.png` (pink -> red), `lamp-head-before-after.png` (pink -> white), `agx-spawn-before-after.png` (global grade).

## Spawn / frozen-play regression — FIXED (Oct 18)

## Mesh index width: UInt16 silently wraps above 65,535 verts (Oct 19)
- **Symptom:** cherry trunks read as long thin connections between trees, and the promenade paving was crossed by a dotted red grid that followed no tile seam. `SignHousing` and `lantern_paper` carried the same slivers (dark, so they hid).
- **Cause:** five builders assigned `Mesh.triangles` / `SetIndices` without setting `indexFormat`: `Cherry.Acc.ToMesh`, `Cherry.PetalMesh`, `LmGeo.ToUnityMesh` (all landmark batches), `Lanterns.Commit`, `FacadeSigns.Commit`. Unity defaults a new mesh to `IndexFormat.UInt16`, and indices past 65,535 **wrap** rather than throw, so triangles weld vertices at opposite ends of a merged chunk. Measured on the baked scene: `cherry_trunk_0` v=433,320, max edge 38.41 m, 20 sliver tris; `ground_petals` v=84,000, max edge **528.94 m**, 3,064 slivers; `SignHousing` 8,268/71,182 tris; `lantern_paper` 1,386; `river_ring` v=77,760.
- **Fix:** set `UnityEngine.Rendering.IndexFormat.UInt32` before the topology when the vertex count exceeds 65,535 (conditional, so small meshes keep 16-bit indices). Rebuilt landmarks: trunk max edge now 0.29–0.45 m and blossom 1.36–1.45 m (the card size), ground petals 0.08 m, zero slivers. Then rebuilt buildings → signage → landmarks, saved Main.unity (1.057 GB) and reopened it: scene-wide audit `vertexCount > 65535 && indexFormat == UInt16` is **0 / 8,165 meshes**.
- **Detection:** a picture cannot tell you how many verts a merged chunk has. Iterate `MeshFilter`s, flag `vertexCount > 65535 && indexFormat == UInt16`, then report the largest triangle edge per mesh — anything larger than the model's own bounds is a wrap.
- **Not yet guarded:** the GLB path in `BuildingsRuntime` (per-model, currently small) and the other single-purpose builders (`GroundMeshes`, `Skyline`, `Billboards`, `StreetLamps`, `TrafficSignals`); none currently exceed 65k, but any new merged batch should pick its index width explicitly.

## MIRAI billboard: invisible screen, wrong winding, stale shader property (Oct 19)
- **Symptom:** the canonical overlook view showed the 未来へ billboard as a flat black slab that dominated the frame; from behind it was a dim panel. The ad texture was bound and the UVs were correct.
- **Cause:** `Billboards.cs` authors every quad/box/beam in SIM space and then mirrors z inside `Quad`, `Hbox`, `Bar` and the inline VideoScreens loop, **without reversing the winding**. The mirror flips handedness. Measured after a rebuild: the screen normal was (0,0,+1) while the overlook lies at −z, so `dot(normal, toOverlook) = −1.00`; `Cull Back` hid the screen and the cabinet behind it was what read as a black slab. `LmGeo.ToUnityMesh` has always swapped indices after the mirror; the signage batch did not.
- **Diagnostic that isolated it:** assign the screen a Cull Off `NeonQuad` material at runtime. The ad appeared immediately, which ruled out the texture, UVs and material and proved the winding. Then flip one primitive at a time.
- **Fix:** reverse each triangle after mirroring — `(b, b+1, b+2)/(b, b+2, b+3)` becomes `(b, b+2, b+1)/(b, b+3, b+2)` — in `Quad`, `Hbox`, `Bar` and the video-screen quads. Side effect: the 7 corner **VideoScreens** (also `Cull Back`) had never rendered from the front either; they now animate on the avenue facades.
- **KAZE TECH:** was the whole 1536x256 sheet mapped to a 15 x 2.5 m quad, so a dark letterboxed bar dominated. Now the UVs are cropped to the glyph box (341..1184, 64..190; aspect 6.76) and the quad is 15 x 2.22 m. Both `billboard_mirai.png` and `kaze_tech.png` were imported with `nPOTScale: ToNearest` (1536 -> 2048); set to `None` so the face and the letters stop stretching by 1.33x.
- **Persistence trap:** `NeonQuad.shader` declared `_Intensity` only as an HLSL uniform, not in `Properties{}`. The build's `SetFloat` showed correctly in the session, but after `open_scene` the material loaded with 0 and multiplied KAZE TECH to black while the ad survived. Declared `_Intensity ("intensity", Float) = 1` in `Properties{}` and saved `KazeTech.mat` with 2.2. This is the EDITOR-CLI rule ("declare every non-array property") caught in the wild.
- **Verified after save + `open_scene`:** screen normal dot(toOverlook) = **+1.00**, ad and KAZE TECH visible at the overlook, corner screens rendering. Shot: `Temp/nk/shots/mirai-final.png` (cf. `view-overlook.png` before).

## Scene-load state: exposure, weather textures, and the light pool (Oct 20)
- **Symptom:** after a scene reload the Lantern Alley view was a flat lavender veil crossed by large, hard-edged translucent quads. Hiding `/Weather` removed it; hiding only its `steam` child removed it too, which ruled out the shader fog and the glass.
- **Cause 1 — exposure was build-only.** `_AgxExposure` was set in `BuildingsRuntime.BuildAll` and nowhere else. `Atmo.PushGlobals` never published it, so a scene loaded without a rebuild read 0: AgX(0) lifts a flat grey and every fog/haze surface turns into a milky veil. Moved the 0.82 into `Atmo.PushGlobals` (NkEditorLighting and PlayerController both call it); `BuildAll` now just calls `Atmo.PushGlobals`.
- **Cause 2 — the steam alpha mask is a runtime texture.** `WeatherDriver.MakePuffAtlas` builds a `Texture2D` that is never serialized; a scene load destroys it, `_WxPuffTex` resolves to Unity's white default, and the radial puff alpha becomes 1.0 over the whole quad. Each ~4.5 m alley mist billboard is then an opaque square — the wedges. Added `WeatherDriver.PushEditorGlobals()` (rebuilds puff atlas / heightfield / emitters, gathers weather lights, pins `_WxCam` and time) and called it from `NkEditorLighting.Push()`; `NkEditorLighting.Tick` also moves `_WxCam`/`_WxPixK` whenever the Scene camera moves, because the rain volume is camera-centred. Do **not** set `Built = true` there: the drip arrays only exist after `Build()`, and DisableDomainReload keeps statics into Play.
- **Cause 3 — the 384-light pool was ranked globally by brightness.** `PushSceneLights` sorted by `color*intensity*range`, so the slots went to the avenue's brightest signs and the alley's own lanterns (intensity 2–6) were dropped: of 61 lights within 60 m only 30 survived. JS lights.js pools by `importance*intensity/(1+d²*0.004)` and re-ranks every 20 frames. Ranking is now distance-weighted, and re-pushed after ~20–25 m of camera travel (`PlayerController.LightRepush` in Play, the NkEditorLighting tick in the Editor). Alley mean luminance went **31 → 67** (browser reference: 93); with 60/61 nearby lights instead of 30.
- **Verified after save + `open_scene`:** `_AgxExposure` 0.82, `_WxPuffTex` 256×256, `_BLPos` 384, alley capture identical to the pre-reload one (`alley-final.png`). Before/after: `alley-before-after.png`.
- **Remaining gap (structural, not a tweak):** `NkPost` applies AgX inside every shader, so the colour buffer reaching HDRP post is already display-referred. Bloom and SSR can only act on values the shader already tone-mapped, which is why neon and lanterns have no halos and the wet pavement does not bloom like the browser even with the right lights. Matching the reference needs tone mapping moved into HDRP post (AgX LUT) and `NkPost` removed from the ~30 shaders; the alley paving also lacks the avenue's planar road reflection.

## Car paint and lamps: per-object state is not scene state (Oct 20)
- **Symptom:** in the Editor every car was a black body with dead head/tail lamps; pressing Play made paint, lamps, beam cones and headlight pools appear. The alley/street captures had cars silhouetted against lit asphalt.
- **Cause 1 — `MaterialPropertyBlock` is runtime state.** A car is one shared mesh plus one shared material; everything individual about it (`_PaintColor`, `_Spin`, `_LightLv`) is written per renderer through a property block. Blocks are not serialized with the scene, so after a load every renderer fell back to the material, whose `_PaintColor` is (0,0,0) and whose `_LightLv` is 0. `_LightLv.x` multiplies the headlamp by 38 and `_LightLv.y/z` drive the LED taillight, so both lamps were literally zeroed. `HealParkedPaint` only re-rolled *parked* paint by name hash, and only from `Update`, i.e. only in Play.
- **Cause 2 — the rest is per-frame output.** `PushCarLights` (28 tail + 14 head fake point lights), `DrawBeams` (cone quads) and `DrawPools` (headlight pools) all run from `VehicleTraffic.Update`, which the Editor never calls; the beam/pool rigs are created at runtime, so a loaded scene has no car lighting at all.
- **Fix:** added `Assets/Game/Vehicles/CarVisual.cs`, a serialized `paint`/`spin`/`lightLv` (+ model type and length) component applied to every car in `SpawnCar`. `SetCarLook`/`PushCarLook` are now the only writers of a car's property block and mirror the values into the component; `CarVisual.Apply()` is the single restore path. `HealParkedPaint` applies all components before its name-hash fallback.
- **Fix — Editor preview:** `VehicleTraffic.PreviewVisuals(camPos)` applies every `CarVisual`, builds a `_preview` car list from the scene (`Vehicles/traffic` children only — parked rows are dark, the hero gets its own slot inside `PushCarLights`, sky AVs only carry nav lights) and runs `PushCarLights`/`DrawBeams`/`DrawPools` against it. `ActiveCars` returns the live `_cars` in Play and `_preview` otherwise. `NkEditorLighting.Push()` calls it, and the 25 m camera-travel branch re-runs it so the new neighbourhood's cars light the view. The cached `_cars` list is also rejected when `_cars[0].go == null`: the statics survive a scene load long after their GameObjects are gone.
- **Two more reload traps found while verifying:** (1) the beam/pool rig must be `HideAndDontSave` and re-created through `CreateRigRoot`, or a save would bake renderers pointing at a `DontSave` material — and a stale rig from before a domain reload must be deleted first or two rigs render at once; (2) leaving Play destroys the `DontSave` material/mesh while the static `_beamInit`/`_poolInit` survive (domain reload is disabled), so `DrawBeams`/`DrawPools` reset the flag when the material is null or the cones never come back outside Play.
- **Persistence requires a rebuild:** the component only exists on cars spawned by the new code, so this needed `RunAsync("vehicles")` (133 parked / 166 traffic / 85 sky AVs, identical counts) plus `save_scene`. Scene stays ~1.057 GB.
- **Verified:** after save + `open_scene`, `_CarLCount` 14 (7 lit cars = 6 traffic within 50 m + the hero), both rigs present, and the reload capture is **byte-identical** to the pre-save one (`Temp/nk/shots/cars-edit-after.png` == `cars-reload.png`). Play round trip: cars lit and moving in `cars-play.png`; after `editor_stop` the rigs rebuild and the view matches `cars-after-play.png`. Before/after: `why-cars.png` vs `cars-edit-after.png`.
- **Still Play-only:** sky AV nav lights (`DrawNavLights`), delivery/driven-car slots, and brake-dependent tail intensity (the preview uses the saved `_LightLv`, i.e. whatever brake state the build ended on).
